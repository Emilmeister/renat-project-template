# Шаблон нового проекта

Готовая организация репозитория для работы с кодовыми агентами,
независимая от языка и фреймворка. Это **не готовое приложение**.

## Начало работы

Переименуй каталог `renat-project-template` в имя своего проекта.
Не накладывай шаблон поверх существующего репозитория с перезаписью файлов.

В [AGENTS.md](AGENTS.md) замени только два поля:
`{{PROJECT_NAME}}` — название; `{{PROJECT_PURPOSE}}` — назначение в одном предложении.
Остальные правила уже готовы. В [docs/development.md](docs/development.md)
зафиксируй известные решения о стеке, платформах и окружении. Отсутствующие
решения оставь явно неопределёнными, а не заполняй предположениями.

Проверь структуру из корня:

```sh
python3 scripts/check-repo.py
```

До замены двух полей скрипт выдаст предупреждение — для чистого шаблона
это ожидаемо. После подстановки полей проверь строгим режимом:

```sh
python3 scripts/check-repo.py --strict
```

Для скрипта нужен Python 3.9 или новее; устанавливать пакеты не требуется.
Без Python документы и правила остаются пригодными для работы.

Открой кодового агента в корне этого каталога и дай первую задачу.
Например, дополни следующий запрос своими данными:

```text
Подготовь этот репозиторий к разработке нового проекта.
Название: ...
Назначение и пользователи: ...
Выбранный стек и ограничения: ...
Первое необходимое поведение: ...

Прочитай AGENTS.md, получи список docs/ и выбери нужные документы.
Замени название и назначение в AGENTS.md; остальные правила не переписывай.
Неопределённые решения не выдумывай. Обнови docs/development.md
на основании того, что действительно настроено и проверено.
Не реализуй приложение, не устанавливай системные пакеты
и не создавай тесты без отдельного поручения.
```

Каталог `.git` в архив не включён. Для нового проекта Git можно инициализировать
самостоятельно; шаблон не создаёт коммиты и не настраивает удалённый репозиторий.

## Структура

```text
renat-project-template/
├── AGENTS.md
├── CLAUDE.md
├── README.md
├── .gitignore
├── .gitattributes
├── .editorconfig
├── docs/
│   ├── how-to-document.md
│   ├── documentation.md
│   ├── development.md
│   └── workflow.md
├── records/
│   └── .gitkeep
├── scripts/
│   └── check-repo.py
└── templates/
    ├── product-scenario.md.tmpl
    └── record.md.tmpl
```

| Путь | Для чего нужен |
| --- | --- |
| [AGENTS.md](AGENTS.md) | Короткая точка входа: контекст, проверки, сохранность |
| [CLAUDE.md](CLAUDE.md) | Импорт того же `AGENTS.md` без дублирования |
| [docs/how-to-document.md](docs/how-to-document.md) | Как сохранять особенности проекта и отделять их от истории |
| [docs/development.md](docs/development.md) | Статус среды, реальные команды и ограничения проверок |
| [docs/workflow.md](docs/workflow.md) | Порядок реализации, исправления, аудита и завершения работы |
| `records/` | Планы, эксперименты и разборы; не включаются в стартовый контекст |
| [scripts/check-repo.py](scripts/check-repo.py) | Проверка целостности шаблона без изменений и сетевых обращений |
| [templates/](templates/) | Две заготовки, которые используются только при реальной задаче |

Файл `.gitkeep` нужен только для сохранения пустого каталога `records/` в Git.
Остальные технические файлы задают формат текста и базовые исключения
для локальных файлов; они не заменяют проверку на утечки секретов.

## Что не создаётся заранее

Структура исходников, каталог тестов, манифесты зависимостей и конфигурация
сборки появятся после выбора технологии. Нет пустых документов об архитектуре,
развёртывании и безопасности, которые изображали бы уже принятые решения.

Nix flakes сохранён как предпочтение подхода, но `flake.nix` и файл фиксации
не выдуманы без реальных пакетов и платформ. Управляющий проект для нескольких
репозиториев, аналитика, автономные исследования и дополнительные службы
появляются только при соответствующей задаче. OpenSpec не требуется.

## Основа и границы адаптации

Шаблон создан из ранее подготовленного архива `renat-new-project-skill.zip`,
в частности `SKILL.md`, его заготовок и справочника о ведении репозитория.
Это **адаптация метода, а не оригинальный репозиторий Рената**.

Первичный источник — предоставленная расшифровка `3. webinar transcrib.txt`.
В её нумерации в чате: короткий `AGENTS.md`, список `docs/` и документирование
особенностей — строки 341–347; разделение `docs/` и `records/` — 379–383;
продуктовые проверки — 467–483 и 507–509; предпочтение Nix — 305–317.

Из навыка сохранены согласование изменений тестов, защита пользовательских
правок и запрет самовольных доступов, установок и развёртываний. Как и в навыке,
это защитные уточнения адаптации, а не дословный регламент выступления.

Дополнения именно этого шаблона: имя `docs/how-to-document.md` по запросу
пользователя, переходник со старого пути, отдельный `docs/workflow.md`,
README, настройки формата текста, `.gitignore` и скрипт проверки целостности.
Две заготовки хранятся отдельно от действующих документов и исторических
записей; в пустом проекте они не создают никаких продуктовых обязательств.
